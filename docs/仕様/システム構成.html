システム構成

markshelf は 1 つの Next.js アプリとして動き、ブラウザ側の React UI が同一オリジンの API を呼び出す。API はドキュメントルート（MARKSHELF_ROOT）のファイルと git リポジトリを読み取るだけで、書き込みは行わない。

全体図

クライアント API ルート サーバー内部 データ源 実線: リクエスト ／ 破線: ファイル変更の通知

API 一覧

エンドポイント呼び出し元処理応答
/api/treepage.tsxルート以下を走査してツリーを作る（.md / .html）JSON
/api/file?path=DetailPanel, PreviewPopupMarkdown 本文を読むJSON
/api/search?q=SearchBar全 Markdown を行単位で部分一致検索JSON
/api/graphLinkGraphリンクグラフを生成（mtime キャッシュ）JSON
/api/asset?path=Markdown 内の画像画像ファイルを返す画像
/api/raw/{path}HTML プレビュー iframeHTML とその相対参照（CSS・JS・画像）を返す各 MIME

/api/timelineTimelinePanelリポジトリ全体の変更タイムラインJSON
/api/diff?path=&hash=DiffView指定コミットでの差分JSON
/api/watchuseRefreshTickfs.watch の変更を SSE で配信。受信側は再取得するSSE

配信形態

npx（ローカル閲覧）

  • bin/cli.mjs が引数のディレクトリを MARKSHELF_ROOT に設定
  • 同梱の .next/standalone/server.js を子プロセスで起動
  • ポートは -p（既定 3000）

Docker

  • /docs をボリュームマウント、または派生イメージに焼き込む
  • BASE_PATH を NEXT_PUBLIC_BASE_PATH に変換し、サブパス配信時は起動時にビルド
  • マウントした .git を読めるよう safe.directory を設定

Vercel

  • docs/ を API 関数のバンドルに同梱して読む
  • 実行環境に git が無いため、履歴・タイムライン・差分は空になる

セキュリティ境界

パスの検証

docs.ts の読み取り関数は、解決後のパスがドキュメントルートの外を指すと null を返す。API はこれを 404 として応答する。

HTML の隔離

HTML は sandbox="allow-scripts" の iframe（allow-same-origin なし）で表示し、/api/raw も CSP sandbox を付けて返す。HTML 内のスクリプトはビューア本体の DOM・ストレージ・API に触れない。

読み取り専用

どの API もファイルや git リポジトリを変更しない。
